## 1. GitHub/Gitee 上其他造梦西游3 相关项目

### 1.1 `constfold/Speculum-4399`（高价值）

<https://github.com/constfold/Speculum-4399>

- 是什么：一个让 4399 Flash 游戏脱离浏览器、脱离账号、离线可玩的工具。README 明确写着"已测试游戏"里
  **第一个就是造梦西游3**（`https://www.4399.com/flash/zmhj.htm?g=3`），也测试过造梦西游2。
- 技术方案（读了 `backends/handler.py` 源码确认）：本质是一个本地 HTTP 反向代理服务器
  （`backends/server.py`），配合本地 **Flash Player Standalone**（不是浏览器插件）去加载游戏。代理层：
  - 对 `*.swf` 请求：转发到真实 4399 CDN，**带 `Referer: http://www.4399.com`**（跟本项目
    `canonical-art-hunt.md` 里独立摸出来的防盗链绕过手法完全一致，属于交叉验证，不是巧合）；下载后本地
    缓存到 `out/cache/`；如果开了 `inject_nested`，会用 `swfutil.jar`（基于 FFDec_lib 构建，跟本项目
    工具链同源）把一个 `_Interceptor.swf` merge 进游戏 SWF 再注入，猜测是给调试/嗅探用的探针。
  - 对 4399 平台层的账号/统计/防盗链控制类接口（`save.api.4399.com`、`stat.api.4399.com`、
    `cdn.comment.4399pk.com/control/ctrl_mo_v5.swf` 等）：直接本地伪造 200/418 响应短路掉，不需要真实
    4399 账号也能存档、玩到底。
  - 构建依赖：Python3 + Java + Apache Flex SDK（`playerglobal.swc` 需 32.0 版本）+ FFDec_lib +
    Playwright（自动嗅探资源列表用）。
  - 协议：AGPL-3.0（`external/` 目录下文件除外）。
- **对本项目的具体可借鉴点**：现在项目复刻 UI 时的参照物是 FFDec 导出的静态位图/对象树坐标，动画时序、
  面板过渡、交互反馈这类"活的"UI 行为只能靠回忆或反复解包猜。如果把这个工具跑起来，等于本地有一份
  **可交互的、真实的原版造梦西游3 客户端**，可以直接录屏/截屏做像素级和动效级双重比对，比本项目已有的
  "Online 客户端 IE 缓存嗅探"路径（`docs/reference/zmxy-online-extracted/`）更直接——不需要 home 机器、
  不需要等真人点界面、Referer 绕过和缓存机制都已经写好现成能用。
  - 风险提示：AGPL-3.0，如果直接拿它的代码合并进本项目（非私有场景）需要遵守 copyleft；私有自用阶段无碍，
    与项目现有"造梦西游素材/kagami 代码血统"的风险级别一致，抬头判断即可。
  - 依赖 Flash Player Standalone + Flex SDK 只在 macOS/Windows 本地跑一次即可，不需要接入到最终产物里。

## 5. Ruffle 跑造梦西游3 的社区先例

**没有针对造梦西游3的直接先例，只有间接、偏负面的信号**：

- GitHub `ruffle-rs/ruffle` issues/PR 搜索"造梦"/"zaomeng"：**零命中**（用 GitHub 官方 search API 
  和站内搜索都确认了），说明没人专门为造梦西游3提过 issue 或写过兼容性报告。
- 相关但不特定的信号：
  - Issue #13943"Cannot run flash games under www.4399.com"（已关闭，对应 PR #16750）：反映的是
    **4399 平台层**的通用问题——网站自身的 Flash 检测脚本会拦截 Ruffle，PR 修的是"CORS 头 + 注入脚本
    绕过网站的 Flash 探测"这类**基础设施层**问题，跟游戏本体的 AS3 字节码/API 覆盖率无关，也就是说
    "能不能打开"这一层已经有人修过，但"打开后游戏逻辑跑不跑得对"完全是另一个问题，这个 PR 不能证明
    任何具体游戏（包括造梦西游3）能正常玩。
  - 知乎文章（`zhuanlan.zhihu.com/p/658533728`）里有一句概括性评价："Ruffle 对游戏的适配较差，仅支持
    小型 Flash 页游……大型游戏（如造梦西游）无法完美适配"——**直接点名了造梦西游**，但这是单一来源的
    泛泛断言，没有给出具体报错、具体卡在哪个环节，可信度中等，只能当"先验倾向负面"的一条弱证据，不能
    当结论。
- 建议：这条线上，另一个 agent 的真机实测结果比继续搜索更可靠——如果实测证实跑不起来或有具体渲染/逻辑
  错误，直接记录实测结论，不必再纠结"社区有没有说过"，搜索引擎这条路已经到头了。
