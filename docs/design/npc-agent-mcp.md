# NPC Agent 能力架构（构想 · 暂缓）

> 状态：**拓展功能，暂缓**。2026-07-07 用户提出，需深入设计后再做，先记录、不着急。
> 这是项目立项核心愿景「agent 驱动 NPC」的完全体方向，值得认真对待，但不要仓促实现。

## 核心构想（用户原话精神）

- **游戏本身作为一个 MCP server**（或类 MCP 的能力提供层）——把游戏的能力（查背包 / 消耗材料 / 产出物品 / 交易 / 移动 NPC / 发任务…）作为受限工具集暴露出来。（用户自陈"不知道这么说是否严谨"——见下"严谨性"讨论。）
- **每个 NPC = 一个 agent。**
- NPC **只能访问「游戏通过 MCP 开放给它的能力」**——工具白名单 = 权限边界。
- **不同 NPC 开放不同能力**（炼丹炉只能合成、老君只能交易…）。
- 权限**可能需要动态**（运行时决定某 NPC 此刻能用哪些工具，如任务解锁新能力）。

## 具体切片：两个 NPC（前一轮已设计）

- **炼丹炉 agent**：工具 = `查配方(itemName)` + `看背包()` + `合成(itemName)`。玩家"帮我合成宣花葫芦"→ 查配方 → 校验背包材料 → 够就消耗材料出货、不够就报缺料。**边界：只能消耗材料换成品，不能凭空发货、不能碰其他状态、不能交易。** 宣花葫芦这类原版法宝走真实合成配方。
- **太上老君 agent**：工具 = `提议交易(给, 要)` + `评估(价值差 + 话术 → 成交概率)` + `执行(roll)`。以贱换尊的概率博弈——拿便宜东西 + 好嘴，有概率换到好货。**边界：只能在背包物品间做交易，不能合成、不能造装备。**
- **权限边界硬性**（服务端强制、越界拒绝）优于软性（prompt 约束）——这才是"明确的行为边界"，且防 LLM 乱来。

## 设计边界：agent 操作既定内容，不创造新内容（用户 2026-07-07 澄清，重要）

- 游戏内 NPC agent 只在**开发者预先定义的内容空间**（装备池 / 配方 / 物品）内**组合操作**：合成已有配方、交易已有物品、获取掉落。
- agent **不创造新内容**。"现场生成一件游戏里本不存在的独一无二装备"本质是**运行时上线一个新装备 = 开发者的职责**，不该是游戏内 NPC 的能力——否则数值 / 平衡 / 设计意图无人管控。此前提过的"炼丹炉现场生成独一无二装备（opencode codegen / DSL 造新词条）"越了这条界，**废弃**。
- 若确实想用 AI 从零造装备，正确位置是**开发侧工具**（离线辅助开发者设计内容 → 人工过审 → 进内容库），与"游戏内 NPC agent 运行时"是两个完全不同的东西，别混。
- 推论：NPC agent 的工具集永远是「在既定内容上做增删查改」这类**有界操作**，不含「生成新内容定义」这类**创作能力**。这也让安全边界天然成立——agent 玩不出设计者没预置的东西。

## 关键设计问题（留给将来）

1. **动态权限**：NPC 的 allowedTools 是静态注册还是运行时可变？
2. **游戏状态作为 MCP 资源**：背包/角色状态如何暴露给 agent 读，合成/交易结果如何安全回写游戏——**双向状态同步**（现状只有单向 world_event，是最大的新增量）。
3. **NPC agent 用什么驱动**：opencode / Claude Agent SDK / 直接 tool-use。
4. **严谨性——真 MCP 还是自定义协议**：真 MCP 的好处是标准化 + 复用工具生态 + 权限模型现成；自定义 WS 工具协议（现状）的好处是轻、贴合游戏帧循环、无握手开销。这是核心取舍。
5. **安全模型**：**能力边界（工具白名单）而非代码沙箱**——正确方向，LLM 只能调被授予的工具，炸不了游戏；不需要 isolated-vm 那套代码沙箱。

## 有没有现成实现

- MCP + per-agent 工具作用域是**现成模式**（MCP server 暴露工具、client 按需授权、不同 client 给不同工具子集）。
- 「**游戏运行时作为 MCP server、给游戏内多个受限 NPC agent 供能**」这种具体形态较新颖，未见直接现成的开源实现，但用现有积木（MCP / tool-use + 权限过滤 + 状态同步）可拼装实现。

## 和现状的关系

现在的 `agent-server`（单个老君 NPC + DSL craft + 单向 world_event + opencode→DeepSeek 驱动）是这个大愿景的**最小雏形**。展开路径：
- 单 NPC → **NPC registry**（每个带 allowedTools + 服务端强制过滤）
- 单向 world_event → **双向状态同步**（agent 读游戏状态 + 结果回写）
- DSL craft → **配方合成 + 分工的能力工具集**
- 自定义 WS 协议 → 评估是否升级为**真 MCP 协议**
