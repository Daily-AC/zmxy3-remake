# social-server 棒：好友/登录/房间后端 + 分配算法纯逻辑（用户 2026-07-08 19:0x 立项）

## 背景与定位

用户新功能线：好友系统 → 前置登录 → 开房 → 多人同房打关卡（联机 co-op）→ 物品所有权/经验灵魂分配/好友转赠。本棒做**大厅层后端 + 分配算法纯逻辑**，联机战斗实时同步是下一棒（架构决策已预拍：MVP 房主权威 + WS 状态广播，服务器只做房间路由，不做战斗仲裁——写进代码注释与 report，本棒不实现）。

## 交付物

新目录 `social-server/`（与 agent-server/ 并列，独立 Node + TypeScript 进程，参考 agent-server 的工程化方式）。

### 1. 账号与登录
- 注册/登录：用户名+密码（bcrypt），JWT 会话（有效期 7 天，secret 走环境变量，配置里绝不落值）。
- 存储 SQLite（better-sqlite3），schema 迁移脚本化（版本化，参考 game 侧 save.ts 的迁移思路）。
- 最小接口：POST /auth/register、POST /auth/login、GET /me。

### 2. 好友
- 申请/同意/拒绝/删除/列表；申请去重；不能加自己。状态机写成纯函数可单测。

### 3. 房间（大厅层）
- 创建/加入/离开/解散；房主转移（房主离开→顺位）；房间成员上限 4；房间绑定目标关卡 id（L1/L2）。
- WS 通道：房内广播骨架（成员进出事件、准备状态、开始游戏信号）。协议消息定义收敛在一个 schema 文件，游戏侧后续复用。

### 4. 分配算法纯逻辑模块（独立文件，重单测）
- **经验/灵魂：在场成员平分**（向下取整，余数给击杀者）——主会话预拍默认，参数化留用户调。
- **掉落：个人独立 roll**——每个在场玩家对同一掉落表独立掷骰，各见各的掉落，无争抢（现代 co-op 惯例，纠纷最少）。
- **物品转赠：服务端事务**——原子转移、防双花（参考 furnace 棒的材料事务防双花测试思路），转赠双方必须是好友。
- 全部纯函数 + 单测；不依赖 HTTP/WS 层。

## 边界

- **不碰 game/ 下任何现有文件**（登录 UI、游戏侧接线是后续棒）。
- 不做战斗内同步、不做聊天、不做匹配——只做上述四块。
- 依赖最小化：express 或 fastify + ws + better-sqlite3 + jsonwebtoken + bcryptjs 级别，别引重框架。

## 验收判据

1. 单测：auth 流程、好友状态机全分支、房间生命周期（含房主转移边界）、分配算法（平分余数/独立 roll 统计性质/转赠双花拒绝）。
2. e2e 冒烟脚本：起服务→注册两用户→互加好友→建房→双双加入→WS 收到广播→开始信号。真实跑通，输出留证。
3. tsc 净；`npm test` 全绿（social-server 自己的测试套件）。
4. report 落 `tasks/social-server-report.md`：接口清单、schema、协议消息定义、预拍决策记录（房主权威/平分/个人 roll）、疑点。
